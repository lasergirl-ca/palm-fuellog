# M5: SD card basics

Started 2026-10-24 while Zoe was out; nothing here is device-verified until she returns.

## Round 1: CSV export, backup and restore (US-19, US-21, US-22)

- `src/csv.c` (plain C, host-tested by `tests/test_csv.c`): the fills CSV. UTF-8 with a BOM,
  RFC 4180 quoting, Palm Latin transcoded through the Windows-1252 table. Columns: Date (ISO),
  Time, Vehicle, Odometer (unit), Trip (unit), Volume (unit), Price (per unit), Total, Currency,
  Rate, Home total (home currency), Payment, Grade, Full, Missed, Discount, one "earned" and
  "redeemed" pair per programme, Notes. The reader side (record reader with quoted newlines,
  either encoding, splitter, header mapper, row parser) is in the same file for the import; the
  test round-trips a fill and parses a paper-log header with miles, US gallons, $/Gallon and KB
  Points, rejecting a 13/31/2019 date with "date is not valid".
- `src/card.c` (new `io` code section): first card volume, the FuelLog folders, an OutStream
  over a VFS file with a 32 KB buffer (seekable, for the XLSX writer later), a byte reader, a
  sorted folder listing, folder delete, file size.
- `src/export.c`: `ExportCsv` writes Export/FuelLog-YYYYMMDD.csv for a vehicle (or all) and a
  year (or all).
- `src/backup.c`: `BackupNow` exports the five databases into Backup/YYYYMMDD-HHMM/ and prunes
  to the Prefs count of sets; `BackupRestore` reads each .pdb's AppInfo schema version first,
  refuses a newer one, then deletes and re-imports the live databases and reopens them (which
  migrates an older schema); `BackupAuto` runs on exit when the weekly backup is on and due.
- **Export** form (Options menu "Export, backup, import..." and Reports > Export): Format
  CSV/XLSX/PDF (XLSX and PDF say "Not yet" until M6), Vehicle, Range (All years or a year),
  Send to SD card or Other Palm (M7), the file name before you tap, Export; Backup with the last
  date and the sets on the card, Back up now, Restore...; Import, Choose a file... **Restore**
  lists the sets newest first and confirms before replacing the log.

Tables inside sectioned functions bit again (the BOM bytes); the checker caught it. The CSV
code sits in the `io` section rather than `xport`, which was a hundred bytes short of its 32 KB.

## Round 2: CSV import with preview (US-20)

- `src/import.c` (io section): two passes over a CSV in Import/. The scan maps the header,
  parses every row with the CSV engine, checks that a vehicle's odometer never falls within the
  file, counts rows ready, duplicates (same vehicle, date and odometer already in the log),
  errors (the first six listed with line numbers), new vehicles (named) and new programmes, and
  notes when a KB Points column maps to the 76 preset by its alias. The write pass creates the
  unknown vehicles and programmes, skips duplicates, and adds the rest sorted by date.
- **Choose a file** lists the CSV files in Import/; **Import** shows the summary and the errors
  under a scrollbar, with "Import N" as the button; "Nothing is written until you tap Import."
  A header that is not a fills header says so and points at a blank export as the template.

Check on the T|X: copy the exported FuelLog-20261024.csv into Import/ and import it: every
row should count as "already in the log" and Import adds 0. Edit one odometer in the file to
make a new row: "1 row ready", Import adds 1.
