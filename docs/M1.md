# M1: Data core

**Status (Oct 22, 2026): done.** Built, host-tested, and checked on the T|X across four runs: create, open, and the migration of a version-less database to schema 1. The exit
criteria are five databases that create, open and upgrade with records packed byte-wise, a
calc library that passes host tests for all units, currencies and EV, and Prefs that persist.

## What is in the code

| File | Holds | Tested by |
| --- | --- | --- |
| `src/records.c` | The five canonical packed layouts (fill, vehicle, programme, service type, service visit) and the AppInfo block, with pack, unpack and sort comparators | `tests/test_records.c`: byte offsets of every field named in the spec, round trips, truncation, short and malformed buffers, sort order |
| `src/units.c` | Distance, volume, economy (fuel and electric) and price conversions between the metric store and the display units, plus labels | `tests/test_units.c`: the spec's factor table, the mock-up samples, and round trips |
| `src/currency.c` | Currency codes, symbols and Excel formats; which currency a new entry gets; the starting rate | `tests/test_units.c` |
| `src/calc.c` | Economy, totals, home-currency conversion, MPG, points earned, kWh/100 km, cost per 100 km, redemption discounts with volume and per-unit caps | `tests/test_calc.c` |
| `src/prefs.c` | The versioned `FuelPrefs` struct, defaults and the upgrade rule; load and save on the device | `tests/test_prefs.c` |
| `src/db.c` | Device only: creates missing databases with the backup bit and the schema version in the AppInfo block, refuses a newer schema, migrates an older one, and adds records in sort order through `DmFindSortPosition` | the M1 button |

Stored values never change with Prefs: every conversion reads the metric store and
produces a display value, or reads typed display digits and produces a metric value, so
US-01's "stored bytes identical after every unit switch" holds by construction.

## Record layouts (bytes)

| Record | Fixed | Variable | Sort |
| --- | --- | --- | --- |
| Fill | 37 | 9 per points entry (0 to 4), then notes to 256 | date, then odometer |
| Vehicle | 47 | none | insertion order |
| Programme | 64 | aliases to 64 | insertion order |
| Service type | 71 | none | insertion order |
| Service visit | 101 | notes to 256 | date |

Every database's AppInfo block is four bytes: schema version (1) and a reserved word.

## A precision decision to make

Prices are stored in thousandths of a currency unit per litre, as the spec says. A price
typed per US gallon is 3.785 times finer than that, so it can come back up to 0.002 $/gal
from what was typed, and a hydro rate of 11.62 ¢/kWh stores as 11.6. The tests allow this.
Storing ten-thousandths instead would make both exact at no cost in record size, since the
field is already 32 bits and the arithmetic is already 64-bit. It is a one-line change in the
spec and the code while nothing is stored yet, and it is not made here.

## What to check on the T|X

Tap M1 on the hello-world form. Expect one line per database with "v1" and its record
count, "Fill round trip: 1 (1 = intact)", "Earlier fill index: 0 (expect 0 of 2)", the fill count
restored, "Prefs v1, home CAD", "Prefs persist: 1", a row counter that grows by one on every
run, "47300 mL = 12495 US gal x1000", and the total time. Tap it twice: the second run should
report the same five databases at v1 with the records it left behind, which is the open path
rather than the create path.

## Device result

First run on the T|X, Oct 22, 2026 (the create path): all five databases report schema v1
with 0 records; "Fill round trip: 1 (1 = intact)"; "Earlier fill index: 0 (expect 0 of 2)";
"Fills after cleanup: 0 (restored)"; "Prefs v1, home CAD"; "Prefs persist: 1 (1 = yes), row 1";
"47300 mL = 12495 US gal x1000"; 30 ms in all.

Second run (the open path): Prefs showed "row 2" as expected, but every database reported
schema v0. The create path had set the version in memory without writing the AppInfo block,
so the next open found none. Fixed: creation now allocates the block with `DmNewHandle` on
the open reference, attaches it with `DmSetDatabaseInfo` and writes the version. A third run
should report v1 everywhere; the second run's migration path will already have written the
block for the five databases that exist.

Third and fourth runs: all five databases at v1, Prefs at rows 3 and 4, every other line as
before, 10 ms each. The third run was also the upgrade path in practice, since it opened the
databases the second run had left at v0.
