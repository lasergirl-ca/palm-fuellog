# M8: Polish and release

## Go PDB reader (US-32; `tools/fuellogdump`), 2026-10-24

`fuellogdump dump <dir>` prints the fills in a backup set as CSV on the Mac, reading the five
.pdb files directly: PDB header and record list, the AppInfo schema version (a newer schema is
refused), and the packed layouts from the spec, with Palm Latin notes transcoded to UTF-8.
`vehicles`, `programmes` and `services` print the other databases. It shares no code with the
app: `tools/mkpdb` builds a fixture set with the app's own pack functions and `make test`
diffs the Go output against `tests/expected_dump.csv`. Build it with
`cd tools/fuellogdump && go build`.

To read a real backup: copy `/PALM/Programs/FuelLog/Backup/<set>/` from the card and run
`fuellogdump dump <that folder>`.

## 5-way on the lists (US-30, first slice), 2026-10-25

On the fill list, Vehicles, Programmes, the Service list and History the 5-way follows
Palm's convention: up and down page the list until a row is highlighted; the first centre
press highlights the top row on screen; from then on up and down move the highlight (the
list scrolls when it leaves the window) and centre opens the row, exactly as a tap would. A
tap also sets the highlight, so coming back from a form lands on the same row. The T|X sends
its 5-way as page keys plus vchrNavChange with the select bit; a Treo's rocker codes are
handled too (rocker up/down always move the highlight). Shared code: `AppRowKey`,
`AppRowHighlight` and `AppRowPlain` in `src/app.c`; the highlight uses the system's
selected-object colours.

Not done from US-30: a focus ring on buttons, fields and popups inside the forms (Palm's own
focus mechanism, `FrmNavigation` resources, is not used), so on the forms the 5-way only
scrolls.

## Launcher icon and version, 2026-10-25

`tools/mkicons.py` draws the icon from shapes (a red pump with a hose on the launcher's blue
oval, lit from the top left, black outline; redrawn Palm-style on 2026-10-26 after the first
flat version) and writes the six bitmaps itself: 22x22 and 44x44 for the launcher, 15x9 and 30x18 for the list view, each in
1-bit and 8-bit. PilRC 3.2 declares a BMP's width and height as C `long`, eight bytes on a
64-bit Mac or Linux, so it misreads every ordinary BMP header ("Bitmap not monochrome, 16,
256 ..."); the script writes the padded header layout PilRC actually reads, which means
these .bmp files open in PilRC and nowhere else. The version resource says 1.0rc1.

## Release candidates (tags v1.0-rc1 to v1.0-rc4)

rc2 (same day) differs from rc1 only in the Export form: the rows that scroll under the
pinned Done button are now hidden until scrolled to, which rc1 got wrong after the Points
row pushed Back up now down by 13 px.

A review pass over the day's commits found four defects, fixed before the tag: the promoted
Other service type was built in a scan buffer that NextTypeId had just overwritten with
another record; a points redemption could spend a lot that had already expired on its date;
the .xls number formatter could write 19 bytes into a 16-byte tail of the row buffer; and
the Stats points line could overrun its 40-byte buffer with a large balance and expiry.

The tag marks the first build with every milestone's code in it. It is not v1.0: M5 to M8
have been checked on the host only, and the LifeDrive and CloudpilotEmu pass (US-31) has not
been done. What to check on the T|X before v1.0 is listed at the end of M2, M3, M5, M6 and
M7, plus: the launcher shows the pump icon at both sizes; the 5-way moves the highlight on
the five lists and centre opens the row; an .xls in Import/ previews and imports; the Points
popup on Export narrows a CSV; the "KB Points to:" popup appears on a preview of a file with
that column; saving a Log Service visit with an Other item offers "Track it".

## Footnote: a native toolchain, later

[User7142/palmdev-macos](https://github.com/User7142/palmdev-macos) ships pre-built prc-tools
(m68k and ARM GCC 2.95.3, SDK 5r3, pilrc, pilot-link) for Apple Silicon, which would let the
app build without Docker. Not adopted: the Docker build is 15 s full and 4 s incremental, and
a compiler change should be checked by comparing the two .prc files byte for byte. Its setup
writes into /usr/local with sudo. Revisit when tidying the build chain after v1.0.

## After rc2: the New Zealand dollar and built-in exchange rates (2026-10-26)

- NZD is the fifth currency (code 4, symbol NZ$) in every currency popup, the CSV/XLSX
  import and export, the Go reader and the Rates form. The spec's currency table gains a row.
- Exchange rates now have a default worth having: `make docker` first runs
  `tools/fetch_rates.py`, which asks the ECB (via api.frankfurter.app) for the day's rates and
  writes `src/rates_default.h` (units per USD, x 1e6, in currency.h order). The app derives
  "home units per unit" from that table for any home currency. If the fetch fails the
  previous header is kept and the build goes on; the header is committed, so the Docker
  container and the host tests never need the network.
- Prefs is v3: eight rate slots, and 0 means "use the built-in rate". A v1 or v2 blob is
  rebuilt field by field (the layout after the rate table moved); a foreign-currency rate
  still at the old 1.0 default is treated as never typed and falls to the built-in rate. The
  Rates form shows the built-in value in a blank slot, a cleared field returns to it, and a
  line says which day's ECB table is baked in.

## After rc2: the 76 preset earns points per gallon (2026-10-26)

Zoe's correction: KB Points are KickBack Points, earned on gallons pumped, not dollars spent,
and not tied to paying with the Phillips 66 card. The preset had been modelled as the card's
cents-per-gallon rebate (money-valued, Card fills only). It is now a points programme: 2 pts
per US gallon on any payment, which matches a 76 receipt (21.215 gal earned 42, and the
balance it prints, 13577, is the paper log's cumulative column), with no
point value or redemption rule because KickBack does not publish one; type yours on the
programme if you know it. Presets only install on first run, so a device that already has
the money version keeps it: open Options > Programmes > 76 / Phillips 66, choose Points,
set Only on to Any payment and Redeem to None.

## After rc3: DateFix and clocks set back (2026-10-27)

Palm OS clocks stop at 2031. [DateFix](https://github.com/User7142/palm-datefix) (User7142)
moves the epoch from 1904 to a start year S (default 1932, so 28 years, 10,227 days, exactly
1,461 weeks: weekdays still match), converts the PIM databases once and patches the system's
date functions. Under it `TimSecondsToDateTime` returns *internal* years (1998 for 2026),
`DateToAscii` and friends show real ones, and the date picker takes and returns internal
years while showing real ones. Zoe's T|X runs it; other Palms do not; backups move between
them. FuelLog stores real dates whatever the clock says:

- `AppClockInit()` at launch: `FtrGet('DtFx', 1)` is DateFix's published S - 1904 (a multiple
  of 4; set on both its Palm OS 5 and 3.5-4 paths), and `DateEpochOffsetDays()` turns it into
  days. Without DateFix, `DateClockShift()` takes a device year more than 14 years behind
  `FUELLOG_BUILD_YEAR` (from the Makefile) as a clock set back 28 years by hand. `AppToday()`
  adds the shift; `AppDeviceToday()` is the raw clock. A hard-reset clock (2004 or so) also
  counts as shifted, which is as wrong as the clock itself; set the clock.
- The three date pickers go through `AppSelectDay(&days, title)`: under DateFix it hands the
  picker internal years and adds the offset back; without it the system picker shows the real
  year it is given. Either way the picker's Today, which is the clock's own date, is moved
  forward by `DateUnshift()` (a date within three years before to one year after the
  device's today). FuelLog calls no other system date function, so DateFix needs no entry
  for it in its application table.
- The service alarm is set in device time: `AppAlarmSeconds()` takes the shift off before
  `TimDateTimeToSeconds`, which DateFix does not patch.
- `DbShiftClockDates()` runs on every launch and after a restore: fills and service visits
  dated inside that window (saved by rc3 or earlier under a shifted clock) move forward and
  the databases are re-sorted. It is idempotent: a moved record is out of the window. The
  last backup date in Prefs moves the same way. Backup set names, exports and CSV/XLSX dates
  therefore carry real dates from now on; sets named 1998... from before this build sort as
  old in the Restore list.
- About's diagnostics line ends in "DateFix +28y" or "clock +28y" on a shifted Palm.

Not detected: a clock that is a few years off, or set back by hand by any amount but 28.
