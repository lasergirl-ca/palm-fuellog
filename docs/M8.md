# M8: Polish and release

## Go PDB reader (US-32; `tools/fuellogdump`), 2026-10-24

`fuellogdump dump <dir>` prints the fills in a backup set as CSV on the Mac, reading the five
.pdb files directly: PDB header and record list, the AppInfo schema version (a newer schema is
refused), and the packed layouts from the spec, with Palm Latin notes transcoded to UTF-8.
`vehicles`, `programmes` and `services` print the other databases. It shares no code with the
app: `tools/mkpdb` builds a fixture set with the app's own pack functions and `make test`
diffs the Go output against `tests/expected_dump.csv`. Build it with
`cd tools/fuellogdump && go build`.

To read a real backup: copy `/PALM/Programs/FuelLog/Backup/<set>/` from the card and run
`fuellogdump dump <that folder>`.

## 5-way on the lists (US-30, first slice), 2026-10-25

On the fill list, Vehicles, Programmes, the Service list and History the 5-way follows
Palm's convention: up and down page the list until a row is highlighted; the first centre
press highlights the top row on screen; from then on up and down move the highlight (the
list scrolls when it leaves the window) and centre opens the row, exactly as a tap would. A
tap also sets the highlight, so coming back from a form lands on the same row. The T|X sends
its 5-way as page keys plus vchrNavChange with the select bit; a Treo's rocker codes are
handled too (rocker up/down always move the highlight). Shared code: `AppRowKey`,
`AppRowHighlight` and `AppRowPlain` in `src/app.c`; the highlight uses the system's
selected-object colours.

Not done from US-30: a focus ring on buttons, fields and popups inside the forms (Palm's own
focus mechanism, `FrmNavigation` resources, is not used), so on the forms the 5-way only
scrolls.

## Launcher icon and version, 2026-10-25

`tools/mkicons.py` draws the icon as pixel art (a red pump with a hose) and writes the six
bitmaps itself: 22x22 and 44x44 for the launcher, 15x9 and 30x18 for the list view, each in
1-bit and 8-bit. PilRC 3.2 declares a BMP's width and height as C `long`, eight bytes on a
64-bit Mac or Linux, so it misreads every ordinary BMP header ("Bitmap not monochrome, 16,
256 ..."); the script writes the padded header layout PilRC actually reads, which means
these .bmp files open in PilRC and nowhere else. The version resource says 1.0rc1.

## Release candidate (build 1025, tag v1.0-rc1)

A review pass over the day's commits found four defects, fixed before the tag: the promoted
Other service type was built in a scan buffer that NextTypeId had just overwritten with
another record; a points redemption could spend a lot that had already expired on its date;
the .xls number formatter could write 19 bytes into a 16-byte tail of the row buffer; and
the Stats points line could overrun its 40-byte buffer with a large balance and expiry.

The tag marks the first build with every milestone's code in it. It is not v1.0: M5 to M8
have been checked on the host only, and the LifeDrive and CloudpilotEmu pass (US-31) has not
been done. What to check on the T|X before v1.0 is listed at the end of M2, M3, M5, M6 and
M7, plus: the launcher shows the pump icon at both sizes; the 5-way moves the highlight on
the five lists and centre opens the row; an .xls in Import/ previews and imports; the Points
popup on Export narrows a CSV; the "KB Points to:" popup appears on a preview of a file with
that column; saving a Log Service visit with an Other item offers "Track it".

## Footnote: a native toolchain, later

[User7142/palmdev-macos](https://github.com/User7142/palmdev-macos) ships pre-built prc-tools
(m68k and ARM GCC 2.95.3, SDK 5r3, pilrc, pilot-link) for Apple Silicon, which would let the
app build without Docker. Not adopted: the Docker build is 15 s full and 4 s incremental, and
a compiler change should be checked by comparing the two .prc files byte for byte. Its setup
writes into /usr/local with sudo. Revisit when tidying the build chain after v1.0.
